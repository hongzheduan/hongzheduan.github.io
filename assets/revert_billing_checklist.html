Revert to Billing

How to turn paid subscriptions back on after the site-wide free-access period.
Everything is driven by one flag — this doc explains what that covers automatically and what still needs a human.

✓ Good news: almost none of this is a manual multi-file edit anymore. Every page's HTML source was kept as its original, paid-mode copy the whole time — a JS flag decides at page-load whether to show the free-access version. Flip the flag off and nearly everything reverts by itself.

The One Step

Open assets/feature_flags.js and change:

window.FREE_ACCESS_MODE = true;
window.FREE_ACCESS_MODE = false;

Commit and push. That's it for the flag-controlled part of the system — see below for what that single edit actually restores, and what it deliberately does not touch.

What Reverts Automatically

All of the following read window.FREE_ACCESS_MODE at runtime. Once it's false, they all fall back to their original paid-mode behavior with no other code changes:

Paywalls re-enable

  • dashboard.html / _cn — Scanner and Index Membership News tool cards lock again for non-subscribers, with the "→ Please choose a plan to view" tag
  • index_news.html / _cn and market_news.html / _cn — redirect non-subscribers to billing.html again
  • index.html / _cn — the hpViewAll gate modal on homepage "View all" links checks real subscription status again
  • baizora_main_form.html / _cn (the Scanner itself) — its own subscription check re-enables (this also fixed a real dormant bug found while wiring the free-access flag: this page was calling a Cloud Function endpoint that doesn't exist, so it was already unconditionally open before the free-access period even started — that's fixed now, so this check will work correctly this time)
  • login.html / _cn — post-login redirect goes back to checking real subscriptionStatus (active/trialing → dashboard, otherwise → billing) instead of always going straight to the dashboard

UI reverts to paid-mode copy

  • Homepage announcement bar — reverts from "Baizora is free for everyone..." back to the 50%-off / 7-day-trial promo text
  • Homepage nav — "Plans" link and the mobile drawer's "Start Free — 7 Days" button reappear (currently hidden)
  • Homepage hero CTA ("Start Free" / "免费体验") — reverts from linking straight to signup.html back to linking to pricing.html (both the top hero block and the lower "Compact CTA" block, EN + CN)
  • Dashboard quick-links — "Plans & Billing" link reappears
  • account.html / _cn — a signed-in user with no real subscription goes back to seeing "No Subscription" + a "Start Free Trial" upsell button, instead of "Free Access" / "Full Platform Access". (Users with a genuinely active/trialing subscription were never affected either way — this only touches the no-real-subscription display branch.)

"Free Tier" naming reverts everywhere

This was the trickiest part to get right, and it's now fully generic. assets/feature_flags.js contains a small function that walks every text node on any page that loads it and renames "Free Tier" → "Top Movers" (CN: "免费版" → "涨幅榜") only while the flag is on. No page's actual HTML source was ever changed to say "Top Movers" — it always says "Free Tier" in the file itself. So once the flag is off, this function simply doesn't run, and every one of these goes back to "Free Tier" automatically, with zero file edits:

  • Homepage nav link, both hero CTA buttons, FAQ mini-question and mini-bullet (index.html / _cn)
  • Dashboard tool card and quick-link (dashboard.html / _cn)
  • All 24 stocks/*.html nav links
  • unusual-volume.html and top-price-movers.html CTA buttons

FAQ content (assets/faq.html / _cn)

  • The new "Is Baizora free?" item disappears again (it's hidden by default in the HTML and only shown by JS while the flag is on)
  • The "How does the 7-day free trial work?" item and the entire "Subscription & Billing" section (subscribe flow, manage/cancel, monthly vs yearly, promo codes, trial-ends policy, duplicate-trial policy, refund policy, "subscribed but can't access dashboard") all reappear
  • "Do I need to sign up to use Baizora?" — the second sentence reverts from "create a free account — no payment required" back to "A paid subscription unlocks the full 500+ stock universe..."
  • "Where do I go after logging in?" — reverts from "you're taken directly to your Dashboard" back to the active-subscriber-vs-unsubscribed routing explanation

What Needs Manual Follow-Up

These were deliberate, permanent edits made outside the flag system — flipping FREE_ACCESS_MODE off does not touch any of them:

File(s)What to do
assets/about.html
assets/about_cn.html		 Positioning line currently reads "a free, convenient scanning tool..." (was "affordable" before). The plan discussed at the time: don't just silently revert the word — write an explicit sentence about the change (e.g. "we've decided to charge a small fee...") so it reads as an honest update, not a quiet reversal.
assets/compare.html
assets/compare_cn.html		 The Pricing table row and closing CTA currently say "Free — full platform, no subscription required." Rewrite back to the real pricing (was "Free Tier available · $9.99/mo or $99/yr — 50% off with code FRIEND50 · 7-day free trial") and point the CTA button back at pricing.html / signup.html as appropriate.
functions/index.js
CHAT_SYSTEM_EN / CHAT_SYSTEM_CN		 The AI chat assistant's system prompt has a direct-answer rule for "is Baizora free?" questions, plus a matching FAQ title entry. Remove or update this rule so the assistant doesn't keep telling users the platform is free once it isn't. Requires a separate deploy — see below.

⚠ functions/index.js is a Cloud Function, not a static page. Editing it and pushing to GitHub does nothing — GitHub Pages doesn't serve Cloud Functions. After editing, deploy separately:

firebase deploy --only functions --non-interactive

sitemap.xml needs no action — it only lists public, no-login pages and was never dependent on billing status.

Verification Steps

  1. 1 Flip FREE_ACCESS_MODE to false in assets/feature_flags.js, commit, push
  2. 2 Wait 1–3 minutes for GitHub Pages to propagate, then hard-refresh (Ctrl+Shift+R)
  3. 3 Sign in as a test account with no active subscription → should land on billing.html, not the dashboard
  4. 4 On the dashboard, confirm the Scanner and Index News cards show the locked "→ Please choose a plan to view" tag for that account
  5. 5 Confirm the homepage nav, hero CTAs, and dashboard quick-links show "Free Tier" / "Plans" again, not "Top Movers" / hidden
  6. 6 Check the FAQ — "Subscription & Billing" section and the trial item should be back, "Is Baizora free?" should be gone
  7. 7 Subscribe as the test account → verify the dashboard unlocks and account.html shows real "Active" status
  8. 8 Manually rewrite about.html / _cn and compare.html / _cn pricing copy (see table above)
  9. 9 Manually update functions/index.js's chat prompt, then deploy with firebase deploy --only functions --non-interactive
