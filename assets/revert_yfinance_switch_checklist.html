Revert the yfinance Switch

How to switch price/volume data back to Tiingo and re-enable live intraday pricing, once there's revenue to justify the cost again.
Reference point: git tag pre-yfinance-switch-2026-08-01 marks the commit right before this switch landed.

⚠ Prerequisite — do this first: confirm the Tiingo subscription is active again before flipping any flag below. Two separate credentials need to be valid: the GitHub Actions secret TIINGO_API_KEY (used by scanner_tiingo.py) and the Firebase Functions environment's own TIINGO_API_KEY (used by functions/index.js's /iex-quotes endpoint — provisioned separately, not shared with the GitHub secret). If either is stale/missing, that half of the switch-back will fail: the scanner exits immediately with "TIINGO_API_KEY environment variable is not set", or live price polling will silently return errors.

Overview

In 2026-08, with no paying customers yet, Baizora switched from Tiingo's paid API to free yfinance for daily price/volume data, and disabled the live intraday price feature sitewide, to cut recurring cost. Both changes are controlled by exactly two flags — nothing else needs code changes to switch back. Fundamentals (SEC EDGAR) were never affected either way.

Prerequisites

  • Tiingo subscription reactivated — a paid plan covering the full ~516-ticker universe's daily historical OHLCV pull.
  • GitHub Actions secret TIINGO_API_KEY (repo Settings → Secrets and variables → Actions) is set to a valid key.
  • Firebase Functions environment has its own valid TIINGO_API_KEY set (check via the Firebase console or however this project's function env vars are currently provisioned — this is a separate value from the GitHub secret above, see functions/index.js around the /iex-quotes handler).

1. .github/workflows/scanner.yml

One line in the top-level env: block flips the scanner's price/volume source back to Tiingo, and restores the original multi-run-per-weekday cadence (4:30 / 5:00 / 5:30 / 6:30 / 11 PM ET) since those later runs exist specifically to retry Tiingo's publish-delay problem.

// Find near the top of the file:
OHLCV_SOURCE_SWITCH: "yfinance"
OHLCV_SOURCE_SWITCH: "tiingo"

Effect: scanner_tiingo.py resumes fetching OHLCV, the SPY benchmark, and BRK-A's price from Tiingo; resumes the Tiingo company-name/market-cap meta call (both in the main scan and the weekend EDGAR-only cron); and the scan step runs on every weekday cron firing again, not just the 4:30 PM one.

2. assets/feature_flags.js

One line re-enables live intraday price polling sitewide.

window.BAIZORA_LIVE_PRICES = false;
window.BAIZORA_LIVE_PRICES = true;

Effect: the "live" price badge and 10–60s intraday polling resume immediately on push (static site, no build/deploy step) across baizora_main_form.html (+ _cn/_free/_free_cn), all 22 stocks/*.html pages, top-price-movers.html, unusual-volume.html, and the homepage ticker bar on index.html/index_cn.html.

⚠ Manual copy fix — not flag-driven: on 2026-08-05, the "Live pricing" marketing bullet was removed from the Monthly plan feature list on pricing.html ("Live pricing · daily scoring after market close" → "Daily scoring after market close") and its CN mirror pricing_cn.html ("实时价格 · 每日盘后评分更新" → "每日盘后评分更新"), since live pricing wasn't actually available. This is static marketing copy, not gated by BAIZORA_LIVE_PRICES — flipping the flag back to true will not restore it. Manually re-add the "Live pricing" clause to both files' Monthly plan bullet list once live pricing is back.

3. Attribution / legal text optional — not required for functionality

Switching the two flags above is enough to restore full Tiingo + live-price functionality on its own. This step is purely cosmetic: while yfinance was primary, every "sourced by" credit and legal-page data-sourcing sentence was reworded to avoid naming a specific vendor (e.g. "Market Data · Updated Daily After Market Close" instead of "Market Data Sourced by Tiingo.com"). That generic wording stays accurate and safe even after switching back — there's no urgency to touch it. Only do this if you specifically want "Tiingo.com" branding restored.

Files touched by the generic-wording change (search each for Market Data · Updated Daily After Market Close / 行情数据 · 每日收盘后更新 / "third-party financial data providers" / "第三方金融数据提供商"):

  • index.html index_cn.html — footer credit + hero bullet
  • baizora_main_form.html _cn _free _free_cn _freetier _freetier_cn
  • baizora_yfinance_beta.html
  • stocks/*.html — all 22, generated from generate_stock_pages.py's template; edit the template, not the individual files, then regenerate
  • assets/terms.html terms_cn.html disclaimer.html disclaimer_cn.html — legal prose sentence + footer credit
  • assets/methodology_2026-05-31.html — has an explicit amber notice box near the top marking the temporary mode; remove it, and revert the cost table's "Market data source" row + the Cloud Functions cost paragraph back to naming Tiingo explicitly

Verification

  • Trigger scanner.yml manually (workflow_dispatch) rather than waiting for the next cron. Confirm the "Run scanner" step actually executes and does not exit with "TIINGO_API_KEY environment variable is not set".
  • Check the run log for Tiingo-specific messages (e.g. "Tiingo data confirmed for …", "Tiingo meta: N/516 names loaded") rather than the yfinance-mode messages ("OHLCV_SOURCE=yfinance — skipping Tiingo publish-delay probe").
  • Spot-check data/latest.json — CompanyName for a few tickers should read Tiingo's cleaner casing again (e.g. "Apple Inc." not "APPLE INC") once the cache repopulates.
  • Load baizora_main_form.html during market hours (9:30 AM–4 PM ET weekday) — confirm the green "live" badge appears and the price/change columns tick every 10 seconds.
  • Check the Firebase console / Google Cloud Functions metrics for /iex-quotes — invocation count should start climbing again from ~0.

Recommended Order

  1. 1 Confirm both Tiingo credentials are valid (prerequisites above) — go/no-go gate, no code change
  2. 2 Edit scanner.yml — flip OHLCV_SOURCE_SWITCH
  3. 3 Edit assets/feature_flags.js — flip BAIZORA_LIVE_PRICES
  4. 4 Commit both together, push
  5. 5 Manually trigger the workflow to verify immediately rather than waiting for the next cron
  6. 6 Run through the Verification checklist above
  7. 7 (Optional) restore Tiingo-branded attribution text — see section 3

After pushing, GitHub Pages can take 1–3 minutes to propagate. Hard-refresh (Ctrl+Shift+R) before testing on the live site.
